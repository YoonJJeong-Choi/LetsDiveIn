# 배송 조회 API 차이점 설명

## 세 가지 배송 조회 API의 차이점

### 1. `GET /api/orders/{orderNo}/deliveries` - 주문별 배송 목록 조회

**용도**: 특정 주문에 포함된 모든 배송 정보를 한 번에 조회

**반환 타입**: `List<DeliveryResponseDto>` (배열)

**예시 시나리오**:
```
주문 #100에 포함된 상품:
- 상품A (옵션: 빨강/L) → 배송 #1
- 상품B (옵션: 파랑/M) → 배송 #2
- 상품C (옵션: 없음) → 배송 #3

→ GET /api/orders/100/deliveries
→ [배송#1, 배송#2, 배송#3] 반환
```

**사용 케이스**:
- 주문 상세 페이지에서 해당 주문의 모든 배송 상태를 한 번에 보여줄 때
- 주문별 배송 현황 대시보드

---

### 2. `GET /api/order-items/{orderItemNo}/delivery` - 주문 아이템별 배송 조회

**용도**: 특정 주문 아이템의 배송 정보만 조회 (주문 아이템과 배송은 1:1 관계)

**반환 타입**: `DeliveryResponseDto` (단일 객체)

**예시 시나리오**:
```
주문 아이템 #50 (상품A, 빨강/L)의 배송 정보만 필요할 때

→ GET /api/order-items/50/delivery
→ 배송 #1만 반환
```

**사용 케이스**:
- 주문 아이템 상세 페이지에서 해당 아이템의 배송 정보만 보여줄 때
- 특정 상품의 배송 상태만 확인하고 싶을 때

---

### 3. `GET /api/deliveries/{deliveryNo}` - 배송 번호로 배송 조회

**용도**: 배송 번호를 알고 있을 때 직접 조회

**반환 타입**: `DeliveryResponseDto` (단일 객체)

**예시 시나리오**:
```
배송 번호 #200의 정보를 직접 조회하고 싶을 때
(어떤 주문/주문 아이템인지는 모르지만 배송 번호만 알고 있을 때)

→ GET /api/deliveries/200
→ 배송 #200 정보 반환
```

**사용 케이스**:
- 배송 추적 페이지에서 배송 번호로 직접 조회
- 관리자가 배송 번호를 알고 있을 때 빠르게 조회
- 외부 시스템(택배사 API 등)에서 배송 번호만 받았을 때

---

## 비교표

| API | 입력 | 반환 | 관계 | 사용 시점 |
|-----|------|------|------|----------|
| `/orders/{orderNo}/deliveries` | 주문 번호 | **배열** (여러 배송) | Order 1:N Delivery | 주문의 모든 배송을 한 번에 볼 때 |
| `/order-items/{orderItemNo}/delivery` | 주문 아이템 번호 | **단일** (1개 배송) | OrderItem 1:1 Delivery | 특정 주문 아이템의 배송만 볼 때 |
| `/deliveries/{deliveryNo}` | 배송 번호 | **단일** (1개 배송) | 직접 조회 | 배송 번호만 알고 있을 때 |

---

## 권한별 접근 가능 여부

모든 API는 다음 권한으로 접근 가능:

- **고객**: 본인 주문의 배송만 조회 가능
- **파트너**: 자신의 상품(Option)이 포함된 배송만 조회 가능
- **관리자**: 모든 배송 조회 가능
