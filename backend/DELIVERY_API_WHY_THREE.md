# 배송 조회 API가 3가지인 이유

## 핵심 답변: **실제 사용 시나리오가 다르기 때문**

각 API는 서로 다른 **입력 정보**와 **사용 목적**을 가지고 있습니다.

---

## 1. `GET /api/orders/{orderNo}/deliveries` - 주문별 배송 목록

### 왜 필요한가?
**입력**: 주문 번호만 알고 있을 때

### 실제 사용 케이스:
```
시나리오: 고객이 "주문 상세" 페이지를 보고 있음
- 주문 번호: 100번
- 주문에 포함된 상품: 상품A, 상품B, 상품C (3개)
- 각 상품마다 배송이 있음

→ GET /api/orders/100/deliveries
→ [배송#1, 배송#2, 배송#3] 반환
→ 화면에 "이 주문의 모든 배송 상태"를 한 번에 표시
```

**필요한 이유**: 
- 주문 상세 페이지에서 **"이 주문의 모든 배송 현황"**을 보여줄 때
- 주문 번호만 있으면 바로 조회 가능 (주문 아이템 번호를 몰라도 됨)

---

## 2. `GET /api/order-items/{orderItemNo}/delivery` - 주문 아이템별 배송

### 왜 필요한가?
**입력**: 특정 주문 아이템 번호만 알고 있을 때

### 실제 사용 케이스:
```
시나리오: 고객이 "주문 아이템 상세" 페이지를 보고 있음
- 주문 아이템 번호: 50번 (상품A, 빨강/L)
- 이 아이템의 배송 정보만 필요함

→ GET /api/order-items/50/delivery
→ 배송#1만 반환
→ 화면에 "이 상품의 배송 상태"만 표시
```

**필요한 이유**:
- 주문 아이템 상세 페이지에서 **"이 상품의 배송 정보"**만 보여줄 때
- 주문 아이템 번호만 있으면 바로 조회 가능
- 주문 번호를 몰라도 됨 (주문 아이템 번호가 더 구체적)

---

## 3. `GET /api/deliveries/{deliveryNo}` - 배송 번호로 조회 ⭐ **가장 중요**

### 왜 필요한가?
**입력**: 배송 번호만 알고 있을 때 (가장 흔한 케이스!)

### 실제 사용 케이스:

#### 케이스 1: 배송 추적 페이지
```
시나리오: 고객이 배송 추적 페이지에 접속
- 고객이 알고 있는 정보: 배송 번호만 (예: "1234567890")
- 주문 번호도, 주문 아이템 번호도 모름

→ GET /api/deliveries/1234567890
→ 배송 정보 반환
→ 화면에 배송 상태 표시
```

#### 케이스 2: 이메일/SMS 링크
```
시나리오: 고객이 배송 시작 알림 이메일을 받음
- 이메일 내용: "배송이 시작되었습니다. 배송 번호: 1234567890"
- 이메일에 링크: https://mall.com/tracking/1234567890

→ 클릭 시 GET /api/deliveries/1234567890 호출
→ 배송 정보 표시
```

#### 케이스 3: 외부 시스템 연동 (택배사 API)
```
시나리오: 택배사에서 배송 상태 업데이트 웹훅을 보냄
- 택배사가 보내는 정보: 배송 번호만
- 우리 시스템: 배송 번호로 배송 정보 조회 후 상태 업데이트

→ GET /api/deliveries/{배송번호}
→ 배송 정보 조회 후 상태 업데이트
```

#### 케이스 4: 고객 문의
```
시나리오: 고객이 고객센터에 전화
- 고객: "배송 번호 1234567890인데 언제 도착하나요?"
- 상담원: 배송 번호만으로 즉시 조회 가능

→ GET /api/deliveries/1234567890
→ 배송 정보 확인
```

**필요한 이유**: 
- **가장 실용적인 API** - 고객이 배송 번호만 알고 있는 경우가 많음
- 배송 추적 페이지의 핵심 기능
- 외부 시스템 연동 필수
- 이메일/SMS 링크에서 직접 접근 가능

---

## 비교: 각 API가 없으면?

### 주문별 API가 없으면?
```
❌ 주문 상세 페이지에서:
   - 주문 번호만 있는데 주문 아이템 번호를 먼저 조회해야 함
   - 여러 주문 아이템의 배송을 각각 조회해야 함 (N번의 API 호출)
   - 불편함!
```

### 주문 아이템별 API가 없으면?
```
❌ 주문 아이템 상세 페이지에서:
   - 주문 번호로 전체 배송 목록을 가져온 후 필터링해야 함
   - 불필요한 데이터 전송
   - 비효율적!
```

### 배송 번호별 API가 없으면? ⚠️ **가장 큰 문제**
```
❌ 배송 추적 페이지 불가능:
   - 고객이 배송 번호만 알고 있는데 조회 불가
   - 이메일/SMS 링크 작동 안 함
   - 외부 시스템 연동 불가능
   - 고객 경험 매우 나쁨!
```

## 결론

| API | 입력 정보 | 사용 빈도 | 필수 여부 |
|-----|----------|----------|----------|
| 주문별 | 주문 번호 | 중간 | 편의성 |
| 주문 아이템별 | 주문 아이템 번호 | 낮음 | 편의성 |
| **배송 번호별** | **배송 번호** | **매우 높음** | **필수** ⭐ |

**최소한 배송 번호별 API는 반드시 필요합니다!**

나머지 두 개는 없어도 동작은 하지만, 있으면 더 편리하고 효율적입니다.

---

## 실제 이커머스 예시

### 쿠팡, 네이버쇼핑 등에서:
1. **주문 상세**: 주문 번호로 모든 배송 보기 → 주문별 API
2. **상품별 상세**: 특정 상품의 배송만 보기 → 주문 아이템별 API  
3. **배송 추적**: 배송 번호로 직접 조회 → 배송 번호별 API ⭐ (가장 많이 사용)

모든 이커머스가 이 3가지 방식을 모두 지원합니다!
